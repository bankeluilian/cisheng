# 此生故事感增强

## 设计
在已确认的刺绣人生画册上，加入具体开场、章节、跨年故事线及真实选择回顾。延续既有用户目标：随机遭遇、出生条件影响生活、结局可保存分享。采用本地原创故事与现有引擎，不接入付费模型或新增登录。

取舍：只加文案不足以产生后续；改成固定主线会挤掉随机人生。因此采用三条可遇见、可放弃、跨年再出现的支线，配合由已发生事件生成的章节及回顾。保留现有概率数据、存档结构与基础玩法。

## 实施
- [x] 为出生开场、章节与真实选择回顾加入无副作用的叙事函数及测试。
- [x] 加入三条原创支线：同学的信、家里的旧椅子、工作里的前辈；每条至少两种选择及一次后续，保存在现有 flags/queue/events/keepsakes 中。
- [x] 出生页加入开场，游戏页展示当前章节及已开启故事，结局与导出共享事件回顾；手机单栏。
- [x] 单元测试覆盖支线分支、跨年触发、JSON存档、旧存档、后续年龄窗口和不消耗随机状态；运行类型与双端构建。
- [ ] 浏览器验证并更新现有公开地址。Sites连接若故障，优先完成 GitHub Pages，准确报告备用站状态。

本轮范围由现有已授权改版及“添加故事感”确定，不另行发起设计审批。界面叙事不得伪装成真实国家历史，出生职业只作出生快照；已故人物不得在后续中被写成在场。

## 验证与审查
- 54项测试、TypeScript、Pages及Vinext构建通过。
- 浏览器实走12岁留地址到20岁收到回信，回应后支线结束；新档案保持空白出生门槛，出生开场可见；390px无横向溢出。
- 独立审查确认回访已出现时误显示约定中断：补回归断言，先失败再修复，状态改为正在发生，完整测试通过。use client指令恢复首行。
- 后续事件旁引用该支线实际历史选择，不把无关的上一事件当作因果。摘要仅使用已存事件，不公开私人笔记。
- Sites连接多次出现HTTP传输失败，无法取得当前发布凭据。优先发布现有GitHub Pages；备用站本轮未同步，源代码及构建保留待恢复。
